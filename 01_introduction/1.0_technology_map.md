## 1.0 技术全景：从 GPU 到 Agent

大模型系统是一摞分层的依赖：硬件提供算力与显存，运行时把张量运算变成 GPU 上的计算函数，模型规定算什么，训练与推理是共用算子、管理不同状态的两条路径，服务与应用建在它们之上。遇到一项新技术，先判断它改的是哪一层、解的是哪一种瓶颈，再看具体实现；排障同样按层定位，一种优化治不了所有层的问题。图 1-0 把这些层次放进同一张地图，后文各章都能在图上找到位置。

### 1.0.1 先看层次，再看两条工作路径

![LLM 技术全景：应用、服务、训练与推理、共享模型计算、算子运行时，以及 GPU 到数据中心的基础设施关系](_images/llm_technology_map.png)

图 1-0：从应用需求向下追踪依赖。纵向箭头表示依赖关系，横向箭头表示训练制品交给推理系统加载，基础设施框内是组织关系。[绘图源文件](https://github.com/yeasy/llm_internals/blob/main/tools/figures/llm_technology_map.py)

**自下而上看能力。** GPU 执行计算，显存保存权重与中间状态；服务器组合计算、主机内存和输入输出设备；集群把多台服务器组织成可调度的资源；数据中心提供机房、供电和散热。集群是逻辑上的资源组织，数据中心是物理设施，二者并非一一对应。软件在这些资源之上实现算子、模型执行、在线服务与应用。

**沿两条路径看工作。** 训练读取样本，经前向、损失、反向和参数更新产生模型。推理加载模型，分两个阶段：Prefill 把整段输入一次送入模型并预测首个新词元，Decode 此后每轮只送入上一轮生成的那一个词元、预测下一个。词元（Token）是模型处理文本的最小单元，可以是一个词、子词片段或单个字符。两条路径共享算子与硬件，管理的状态不同：训练要保存梯度、优化器状态与恢复点；推理要管理请求队列和 KV 缓存，即各层为已处理词元保存、供后续各轮直接读取的中间结果。这几个术语的正式定义见 [1.4.3 节](1.4_transformer_idea.md)。RLHF 等在线后训练会反复调用生成服务，两条路径并不隔绝。

**三个量级。** 每 10 亿参数的 FP16 权重约占 2 GB 显存。Llama 3 8B 每处理一个词元，KV 缓存增加约 128 KiB（见 [10.2 节](../10_inference_optimization/10.2_kv_cache.md)）。Decode 每生成一个词元，要把全部权重从显存读一遍（见 [10.1 节](../10_inference_optimization/10.1_bottleneck.md)）。第一个数决定模型放不放得下，第二个数决定一张卡能同时保留多少上下文，第三个数说明逐词元生成的速度受显存带宽限制多于受算力限制。

**区分模型与框架。** Transformer 定义计算结构，PyTorch 等框架组织计算，vLLM 等引擎组织高效生成，Agent 宿主组织工具与任务，它们不相互替代。图按主要职责定位，实际软件可以跨层，例如 vLLM 同时提供服务入口、调度与模型执行（见 [vLLM 架构说明](https://docs.vllm.ai/en/latest/design/arch_overview/)）。

### 1.0.3 用一个问题串起整张地图

假设用户询问“公司的差旅住宿上限是多少”。模型已在服务启动时加载，本次请求按以下顺序执行：

1. **应用整理任务。** RAG 检索当前用户有权读取的制度片段，把来源与问题放入上下文；固定的检索问答流程不一定需要 Agent。
2. **服务接收请求。** 网关校验身份和配额，路由到可用的模型实例。这一层处理的是请求，不是矩阵。
3. **Prefill：处理整段输入。** 引擎安排批次与 KV 空间，把问题和制度片段送入模型；模型计算各层表示、建立 KV 缓存，用最后位置的输出预测首个新词元。
4. **Decode：继续生成。** 每轮输入上一轮生成的词元，读取并更新 KV 缓存，预测下一个词元；结果可以立即流式返回。重复到满足停止条件后回收请求状态，可复用的前缀缓存按引擎策略保留。
5. **应用检查并交付。** 应用展示答案与引用；若要执行报销等动作，须另行校验参数、权限与授权，模型生成的调用不是执行许可。

步骤 3、4 每次都走同一条计算链：模型张量运算，GPU 内核与必要的跨卡通信，计算结果。内核（kernel）是指在 GPU 上执行的一个计算函数，例如一次矩阵乘法。读显存和跨节点传输都发生在 Prefill 与 Decode 内部，不是生成结束后的另外两个阶段。各步的矩阵形状与 KV 缓存的更新见 [3.8 节](../03_components/3.8_gpt_inference_flow.md)。

这次问答不更新权重：权重在上线前由训练路径产生。检索到新制度、复用 KV 缓存和把知识训练进模型，是三个不同的过程。

排障沿同一张地图定位。答案依据错误，先查检索与生成；首词元慢，把排队与 Prefill 拆开看；逐词元输出慢，查 Decode、访存和通信；扩卡不增吞吐，查切分与互连。具体判据见 [11.13 节](../11_serving/11.13_best_practices.md)。
