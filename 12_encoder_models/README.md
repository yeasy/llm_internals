# 第十二章：编码器系列模型

第三部分的整套推理服务都架在“逐词元把回答生成出来”这个前提上。文本分类、关系抽取、语义相似度、检索这类任务不需要生成，只需要一份好的文本表示。去掉因果掩码、让每个位置都读到整句的编码器，正是为这件事设计的。

本章围绕一个问题展开：任务只要一个向量或一个分数时，一次双向前向能做到什么，代价落在哪里。编码器用监督密度和生成能力换来双向上下文；此后的每条改进只动训练配方、参数存放、预训练目标、注意力范围中的一处，它能不能留到今天，取决于省下的是不是真正受限的那一项开销。

[12.1 节](12.1_bert.md)的 BERT 是基线，交代结构、预训练加微调的范式和两条硬边界。[12.2 节](12.2_roberta_albert.md)是三条互不相干的改进轴：配方、参数存放与目标。[12.3 节](12.3_longformer_bigbird.md)先交代长度上限这条路线的来历与去向，再讲编码器今天的主要用途：句向量、检索与重排序。可顺序通读，也可只查用得上的那一节。正文的参数量只给到够下结论的精度，逐项对账与配置键放在[附录 A.3](../appendix/a3_model_reference.md)与[附录 A.7](../appendix/a7_framework_recipes.md)。
