# 第九章：解码策略：模型如何生成文本

前向交出的是一行分数，不是一个词元。本章的主线是这一行 logits 变成词元的那条处理链：约束与偏置、惩罚、温度、截断、选词、停止判定六个环节，次序固定，选出的词元再送回模型，成为下一轮的条件。贪心与束搜索、各种采样、约束解码各是链上的一环；推理时扩展把这条链重复几遍或拉长；扩散语言模型换掉了“从左到右、一次一个词元”这个前提，由此可以分清自回归的哪些代价是生成固有的，哪些只是这种分解方式带来的。

沿着这条线索，本章依次回答六个问题：

- 文本是一个词元接一个词元生成出来的，这个循环每一步重算什么、又复用什么？（[9.1 节](9.1_autoregressive_decode.md)）
- 每步都选概率最高的那个词元，为什么不等于整句最优？（[9.2 节](9.2_greedy_beam.md)）
- 把随机性放回来之后，多样性与质量之间的阈值该怎么定？（[9.3 节](9.3_sampling.md)）
- 采样只看概率，凭什么保证输出是一个合法的 JSON？（[9.4 节](9.4_constrained.md)）
- 在解码阶段多投入计算，能换来更强的推理吗？（[9.5 节](9.5_test_time_scaling.md)）
- 「从左到右、一次一个词元」这个前提，本身是必须的吗？（[9.6 节](9.6_diffusion_lm.md)）

9.5 节和 9.6 节的成本账会用到「访存受限」和「拐点」两个概念。[3.8.8](../03_components/3.8_gpt_inference_flow.md) 已给出直觉：单请求 Decode 每轮要把权重读一遍却只算一行，耗时由显存带宽决定，算力大量闲置。严格的定义和推导在[第十章](../10_inference_optimization/README.md)，读这两节不需要先读第十章。
