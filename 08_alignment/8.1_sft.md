## 8.1 监督微调：教模型“怎么回答”

“法国的首都是什么？”可以和“法国的首都是巴黎”放在一起，作为一条示范。前半段给模型看用户怎么问，后半段示范助手怎么答。

用正确示范继续训练已有模型，叫**监督微调**（Supervised Fine-Tuning，SFT）。和预训练一样，模型仍然预测下一个词元。训练时先让模型读问题，再提高它生成示范答案的概率。只想教它怎样回答时，可以只对回答里的词元计损失。微调的数据量通常比预训练小，集中在需要改进的任务上。实际训练和评测的命令见 [A.7 的本地微调示例](../appendix/a7_framework_recipes.md#own-model-sft)。

### 8.1.1 从续写到对话

预训练教模型接着给定的文本往下写。给它“法国的首都是”，它可能续出“巴黎，位于塞纳河畔……”。直接问“法国的首都是什么？”，它既可能回答，也可能接着写“这是一道地理题……”。

先把一条用于 SFT 的示范写成便于阅读的对话：

```text
用户：法国的首都是什么？
助手：法国的首都是巴黎。
```

训练程序需要知道哪句是用户的问题、哪句是助手的回答。以 Hugging Face 的训练库 TRL 为例，它的[会话数据格式](https://huggingface.co/docs/trl/dataset_formats)用字段记录角色和内容。下面是 JSONL 文件中的一行，这种文件每行保存一个 JSON 对象。

```json
{"messages":[{"role":"user","content":"法国的首都是什么？"},{"role":"assistant","content":"法国的首都是巴黎。"}]}
```

`role` 表示谁在说话，取值由所用的框架或平台约定。这里用 `user` 表示用户，`assistant` 表示助手。问题和回答写在 `content` 里，可以用中文。助手消息里的回答就是要让模型学的示范。

[聊天模板](https://huggingface.co/docs/transformers/chat_templating)把消息排成模型需要的词元顺序，并按模型的约定标出角色。[3.8.2 节](../03_components/3.8_gpt_inference_flow.md)的教学模板是 `⟨user⟩ 2 + 3 = ⟨assistant⟩`。开始推理时，服务端把表示“助手开始回答”的标记放在末尾。训练和推理使用同一套模板，模型就能见到熟悉的角色标记。

模型答非所问或迟迟停不下来时，先检查训练和推理是否用了同一套模板，训练样本是否保留了结束词元，以及系统提示的用法是否一致。训练损失下降时，这些问题仍可能存在。

### 8.1.2 怎样计算一条样本的训练损失

练习回答“法国的首都是什么？”时，模型仍要读到问题，才知道该答什么。训练可以只检查它对回答中各个词元的预测。给正确词元的概率越低，这个位置的损失就越大。

为了逐个看清预测目标，下面用 3.8 节更短的算术题。把提示词 `⟨user⟩ 2 + 3 = ⟨assistant⟩` 与回答 `5 。 EOS` 接成 9 个位置，EOS 表示回答结束。模型在每个位置预测下一个词元。图 8-1 把每个位置的输入和预测目标并排写出，并用一排 0 和 1 标记哪些目标计入损失。这排标记叫**掩码** $$m$$。

![一条 SFT 样本的词元、目标与掩码](_images/ch08_sft_loss_mask.png)

图 8-1：一条 SFT 样本中参与计算损失的位置（[生成脚本](https://github.com/yeasy/llm_internals/blob/main/tools/figures/ch08_sft_loss_mask.py)）。蓝色表示提示词，青绿色表示回答与计入损失的位置。词元序列沿用 3.8 节的教学模板，`-log p` 的三个数值用于示意。图内的角色标记 `〈user〉` 对应正文的 `⟨user⟩`。

位置 1 到 5 的目标都是提示词，掩码为 0。位置 6 输入 `⟨assistant⟩`，预测回答的第一个词元 `5`，所以 $$m_6 = 1$$。位置 7、8 也预测回答中的词元。位置 9 是 EOS，后面没有预测目标。因此，9 个位置里有 3 个计入损失。

SFT 和预训练一样，用交叉熵来计算损失。假设模型在这三个位置给正确词元的概率分别是 0.698、0.896、0.399，取负对数得到的 $$-\log p$$ 分别为 0.36、0.11、0.92。把这三项加起来，再除以参与计算的位置数。

$$
\mathcal{L} = \frac{0.36 + 0.11 + 0.92}{3} = 0.463
$$

对任意一条样本，都可以用掩码写出同样的计算。在位置 $$t$$，掩码 $$m_t$$ 为 1 时计入该位置的预测，为 0 时跳过。位置 $$t$$ 预测的是位置 $$t+1$$ 的词元，所以要看下一个词元是不是回答的一部分。按当前词元的位置来判断会错开一格。分母 $$\sum_t m_t$$ 就是参与计算的位置数。

$$
\begin{aligned}
\ell_t &= -\log p_\theta(x_{t+1}\mid x_{\le t})\\
\mathcal{L} &= \frac{\sum_t m_t \ell_t}{\sum_t m_t}
\end{aligned}
$$

**训练模型结束回答时，应把对应的结束词元计入损失。** 上例用 EOS 表示它，其 $$-\log p$$ 最大（0.92），说明模型在这个位置预测结束的概率较低。漏掉它，损失会降到 $$(0.36 + 0.11) / 2 = 0.235$$，但模型在这条样本上也失去了学习何时结束的机会。实际的聊天模板通常会用一个专门的词元标记回合结束。

**怎样设置训练范围。** 聊天模板负责按角色排好消息，训练器还需要知道哪些位置计入损失。用 TRL 的监督微调工具 `SFTTrainer` 时，可以按目标选择数据写法。

- **整段都参与训练。** 用完整的 `messages` 列表或单个 `text` 字段时，默认对整个序列计损失。在 `messages` 里，`user` 和 `assistant` 用来标明是谁在说话。
- **只练习最后一次回答。** 把问题和对话历史放在 `prompt`，最后一次回答放在 `completion`。这种写法默认只对 `completion` 计损失，由 `completion_only_loss` 控制。
- **练习对话中的每一次助手回答。** 保留完整的 `messages`，设置 `assistant_only_loss=True`。聊天模板需要用 `{% generation %}` 和 `{% endgeneration %}` 标出每段助手回答的起止位置。多轮对话中，每段标出的回答都可以计入损失。

训练前可以抽查一个实际批次。先读模型的输入 `input_ids`，确认问题仍在，再看用于计算损失的标签 `labels`。PyTorch 的 `CrossEntropyLoss` 默认用 `ignore_index=-100` 标记跳过的位置，求平均时也不数这些位置。只训练助手回答时，用户和系统消息对应的标签应当是 `-100`。再确认目标助手回合和结束词元都保留在标签里。各开关的取值见[附录 A.7](../appendix/a7_framework_recipes.md)。

### 8.1.3 微调为什么常用较小的学习率

全参数 SFT 通常从较小的学习率起步。基础模型在预训练中已经学到语言和常识。微调希望它学会怎样完成特定任务，同时保住已有能力。

**用 Llama 2 算一遍。** Meta 的语言模型 [Llama 2](https://arxiv.org/abs/2307.09288) 用了 2 万亿个词元做预训练。团队为监督微调收集了 27,540 条人工标注，训练了两轮。假设每条标注有 500 到 2,000 个词元，单算这批标注，模型两轮读到的词元约有 2,750 万到 1.1 亿个，大致相当于预训练用量的七万分之一到两万分之一。

**为什么要控制更新幅度。** 如果微调样本大多是同一类任务，反复训练就会让这类样本主导权重更新。步长太大或训练轮数太多，模型可能在新任务上做得更好，却在训练数据没有覆盖的任务上退步。严重时会出现**灾难性遗忘**（catastrophic forgetting）。较小的学习率能限制每步更新，已有能力保留了多少，还要用独立样本来检验。训练参数的作用见 [6.1 节](../06_training_techniques/6.1_loss_optimizer.md)，回归评测见 [8.5 节](8.5_practice.md)。

**怎样选初始学习率。** Llama 2 用余弦调度逐步降低预训练学习率，最后降到峰值的 10%。7B 与 13B 最后是 $$3.0\times10^{-5}$$，34B 与 70B 是 $$1.5\times10^{-5}$$。它的 SFT 取 $$2\times10^{-5}$$，相当于峰值 $$3\times10^{-4}$$ 的 1/15，和预训练结束时接近。可以从这个量级试起。艾伦人工智能研究所（Ai2）的 Tülu 3 是另一组公开例子。表 8-1 中的学习率分别为 $$5\times10^{-6}$$ 和 $$2\times10^{-6}$$，比 Llama 2 低 4 到 10 倍。

### 8.1.4 打包与损失归一化：两个容易忽略的选择

指令样本的长度从几十到几千词元不等，把每条都填充到 4,096 会在空位上花掉不少计算。**打包**（packing）把多条短样本拼进同一条长序列，尽量填满。Llama 2 把提示词与回答接在一起，用特殊词元分隔，并把提示词上的损失置零。

打包带来一个必须回答的问题：拼在一起的两条样本，后一条能不能读到前一条？注意力默认是因果的，只屏蔽未来，不屏蔽“上一条样本”。不加处理时，后一条样本的每个位置都会把前一条当成上下文。要避免这一点，需要一个块对角的注意力掩码，让每条样本只看见自己。以 3 个词元的样本 A 与 2 个词元的样本 B 拼成一条序列为例，行是发出注意力的位置，列是被看的位置，1 表示允许：

```text
     A1 A2 A3 B1 B2
A1    1  0  0  0  0
A2    1  1  0  0  0
A3    1  1  1  0  0
B1    0  0  0  1  0
B2    0  0  0  1  1
```

每块仍用下三角掩码，只读本条样本里已经出现的词元。B 的两行在 A 的三列上全为 0，因此 B 看不到 A。这叫序列内注意力隔离。FlashAttention 是一类计算注意力的高效内核，可通过变长序列接口接收各条样本的起止偏移。模型通常能忽略无关前缀。处理长样本或格式要求严格的任务时，相邻样本的干扰更值得检查。

**损失按什么归一化。** 上面的公式按词元平均，分母是本批次所有计损失位置之和。另一种写法是先在每条样本内部平均，再跨样本平均。差别在权重分配：按词元平均时，所有回答词元等权；按样本平均时，每条样本等权，长回答里单个词元的权重被摊薄。100 词元的回答里每个词元的权重是 1/100，1,000 词元的回答里是 1/1000，相差 10 倍；短回答的结束词元也会得到更高的权重。生成的回答会不会随之缩短，要用同一批提示实测。打包之后 `CrossEntropyLoss` 的均值归约给出的是按词元平均，本节的公式取这一种。[8.2.4 节](8.2_rlhf.md#rl-verifiable-rewards)也讨论长度对损失权重的影响。GRPO 还要区分优势为正和为负的情形。

### 8.1.5 数据质量的影响

增加示范之前，先看现有示范的质量和覆盖面。[LIMA 论文](https://arxiv.org/abs/2305.11206)用 LLaMa 65B 做了一次对照。LIMA 用 1000 条精心编写的指令和回答做 SFT，在人类偏好评测中胜过了同样用 LLaMa 65B、在 52,000 条 Alpaca 指令数据上微调的模型。作者提出**表层对齐假说**（Superficial Alignment Hypothesis），认为模型的大部分知识与能力来自预训练，指令微调主要教它怎样把这些能力用到回答里。

理解这个结果要看实验条件。基座是已经学到相当多知识的 65B 模型，评测请人比较单轮指令的回答。知识题的准确率要另外测试。提示词的多样性不变时，增加同类样本的收益会递减。原始数据缺少多轮对话，作者补上 30 条手工编写的多轮对话后，模型的多轮表现明显改善。缺少某类示范时，先补上这类任务，再考虑是否需要另外增加一万条现有类型的样本。

Llama 2 的团队也发现高质量样本很重要。他们认为数万条标注已足以取得较好的结果，最终收集了 27,540 条。两组实验的标注量相差约 27 倍。挑数据时，先看它覆盖了多少种提示，再看有多少条。反复加入同一类样本，原来漏掉的任务仍然没有示范可学。

[Tülu 3](https://arxiv.org/abs/2411.15124) 的 SFT 数据约有 94 万条，既有公开数据集里的样本，也有为特定技能合成的示范。这样的配方需要决定每类任务放多少样本，以及哪些能力还没有覆盖。合成数据可以较低的成本快速补充示范，用它训练时要留意 [8.5.3 节](8.5_practice.md)所示的风险。

### 8.1.6 两份公开的 SFT 训练配置

表 8-1 比较 Llama 2 和 Tülu 3 的公开 SFT 配方。

| 超参数 | Llama 2 Chat（7B 到 70B） | Tülu 3 8B | Tülu 3 70B |
| --- | --- | --- | --- |
| 学习率 | $$2\times10^{-5}$$ | $$5\times10^{-6}$$ | $$2\times10^{-6}$$ |
| 调度 | 余弦 | 线性 | 线性 |
| 权重衰减 | 0.1 | 0.0 | 0.0 |
| 有效批大小 | 64 条打包序列 | 128 条样本 | 128 条样本 |
| 最大序列长度 | 4,096 | 4,096 | 4,096 |
| 训练轮数 | 2 | 2 | 2 |
| 损失掩码 | 提示词位置置零 | 同左 | 同左 |

表 8-1：两份公开 SFT 配方，分别取自 [Llama 2 论文](https://arxiv.org/abs/2307.09288)和 [Ai2 的 Tülu 3 复现命令](https://github.com/allenai/open-instruct/blob/main/docs/tulu3.md#finetuning)。两份配方都训练 2 轮，序列上限都是 4,096 词元。Llama 2 把短样本打包进长序列，每批处理约 $$64 \times 4{,}096 \approx 26$$ 万词元。Tülu 3 的复现命令未启用打包，批大小按样本数计算。

换框架时参数名会变，要核对的是三件事：标签掩码放在哪一层做、批次按词元还是按样本计、学习率相对预训练末端处在什么位置。

SFT 可以用一条示范教模型怎样回答首都问题。有些任务会有多种正确做法，例如一道数学题可以有几种解法。示范很难写全时，可以让模型自己尝试，再根据结果给分，见 [8.2 节](8.2_rlhf.md#rl-training-loop)。模型学会回答的样式后，仍要核对它是否把任务做对，见 [8.5.3 节](8.5_practice.md)。
