# 第十一章：推理引擎与生产部署

本章只有一条主线：Decode 的每一步要把全部权重读一遍，再把批内每个请求的 KV 各读一遍。Llama 3 8B 在 H100 上、每个请求带 1,000 个词元的上下文时，一步要读 `16.06 + 0.131 × B` GB：批大小 B 从 1 升到 32，每步只从 4.8 ms 慢到 6.0 ms，总吞吐却从约 200 升到约 5,300 词元/秒。批越大，每一步越慢，总吞吐仍在涨。推理引擎的每个部件都在这条曲线上做文章：连续批处理让批不空，分页的 KV 管理让批更大，分块 Prefill 给每一步的时长设上界，前缀复用少算也少存，量化与多卡改的是曲线的两个系数，调度器决定工作点落在曲线的哪里。

第十章的 KV 缓存、量化、投机解码都是单项技术，把它们整合成一个能同时服务成百上千个请求的运行时，是从研究走到产品的一步。本章在[技术全景图](../01_introduction/1.0_technology_map.md)中连接推理执行、模型服务与底层资源。全章的算例共用一组常量，集中列在 [11.1.1](11.1_engines_overview.md)。用到的系统背景就地补出，不要求预先掌握：操作系统的分页与碎片在 [11.2.3](11.2_continuous_batching.md)，排队论的利用率在 [11.3.6](11.3_scheduler_loop.md)，约束解码的自动机在 [9.4 节](../09_decoding/9.4_constrained.md)。对应的 [A.7 服务实验](../appendix/a7_framework_recipes.md)提供 vLLM 与 SGLang 的本地启动、统一负载和指标核对步骤，各节迁出的实现对照也在那里。
