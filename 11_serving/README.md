# 第十一章：推理引擎与生产部署

第十章的 KV 缓存、量化、投机解码都是单项技术；把它们整合成一个能同时服务成百上千个请求的运行时，是从研究走到产品的一步。本章拆开这个运行时：调度器每一轮怎样选请求，KV 显存怎样分块、共享与回收，前缀怎样跨请求复用，多个 LoRA 适配器与语法约束怎样挤进同一次前向，模型怎样切到多张卡、Prefill 与 Decode 怎样分到两组机器；随后把这些机制对到 vLLM 与 SGLang 的源码上，最后落到硬件选型与上线后的指标。

本章的十三节按“机制—扩展—实例—工程”四组排列，各自回答一个问题。

- 直接用 `model.generate()` 上生产会卡在哪里？（[11.1 节](11.1_engines_overview.md)）

- 每一轮谁参加、各算几个词元；显存不够时牺牲谁、怎样恢复？（[11.3 节](11.3_scheduler_loop.md)）
- KV 池有多大，块怎样分配、共享与回收，装不下时换出还是重算？（[11.4 节](11.4_kv_memory_management.md)）
- 两个请求开头一段词元相同时，怎样找到并复用这一段的 KV？（[11.5 节](11.5_prefix_reuse.md)）
